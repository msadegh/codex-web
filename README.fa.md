# کدکس وب (Codex Web)

**فارسی** · [English](README.md)

[![CI](https://github.com/msadegh/codex-web/actions/workflows/ci.yml/badge.svg)](https://github.com/msadegh/codex-web/actions/workflows/ci.yml)

یک رابط مرورگری غیررسمی و محلی‌محور برای
[Codex CLI](https://developers.openai.com/codex/cli/) و
[Claude Code CLI](https://code.claude.com/docs/en/overview) نصب‌شده روی سیستم
است. خود Codex یا Claude همچنان روی لپ‌تاپ شما یا سروری که در اختیارتان است
اجرا می‌شود؛
مرورگر فقط رابط چت مناسب‌تری برای متن فارسی، راست‌به‌چپ و متن ترکیبی
فارسی/انگلیسی فراهم می‌کند.

> [!IMPORTANT]
> Codex Web پروژه‌ای مستقل و جامعه‌محور است و وابستگی، تأیید یا پشتیبانی رسمی
> از طرف OpenAI یا Anthropic ندارد.

## امکانات

- استفاده از login، تنظیمات، مقادیر سطح اول profileها، skillها، MCP serverها،
  sessionها، sandbox و approvalهای Codex CLI نصب‌شده
- اتصال به sessionهای Claude Code CLI با streaming، انتخاب مدل، تاریخچهٔ محلی
  گفتگو و حالت‌های permission خود Claude
- اجرای هم‌زمان چند گفتگوی ایزوله در یک تب مرورگر
- نمایش سؤال‌ها و درخواست‌های تأیید Codex فقط در گفتگوی مربوط به خودشان؛
  Claude به‌صورت غیرتعاملی اجرا شده و از permission mode و ruleهای خودش پیروی
  می‌کند
- استریم پاسخ، فعالیت ابزارها، plan، تغییر فایل‌ها و خروجی فرمان‌ها
- Plan mode بومی Codex و Goal mode ماندگار با امکان مکث، ادامه، ویرایش، حذف و
  نمایش پیشرفت هدف
- Dictation مرورگر برای تبدیل گفتار به متن قابل‌ویرایش داخل composer
- ساختاردهی تطبیقی پاسخ‌های چندبخشی Codex با headingهای معنایی و فهرست واقعی،
  در کنار ساده نگه‌داشتن پاسخ‌های کوتاه و حفظ تم بصری فعلی Codex Web
- انتخاب هم‌زمان چند تصویر یا Paste مستقیم اسکرین‌شات و درج مسیر سمت سرور
- صف‌کردن prompt بعدی هنگام اجرای turn و quoteکردن بخش انتخاب‌شدهٔ پاسخ داخل
  composer
- بستن و بازکردن سادهٔ سایدبار تاریخچه با حفظ انتخاب کاربر
- جابه‌جایی بین پیام‌های خودتان و دکمهٔ رفتن مستقیم به انتهای گفتگو
- اعلان صوتی یک‌باره برای پایان کار گفتگوهای باز و پس‌زمینه
- بدون دیتابیس، build step، framework یا dependency اجرایی npm

رابط کاربری در حال حاضر فارسی‌محور است. README به دو زبان فارسی و انگلیسی
ارائه شده است.

## ابتدا امنیت

Codex Web یک پنل کنترل برای coding agent است. دسترسی به صفحه می‌تواند،
مخصوصاً هنگام استفاده از `--yolo` در Codex یا `bypassPermissions` در Claude،
تقریباً معادل دسترسی shell با مجوزهای کاربر سیستم‌عاملی باشد که برنامه را اجرا
کرده است.

- سرور HTTP عمداً فقط روی `127.0.0.1` گوش می‌دهد.
- برنامه احراز هویت تحت وب داخلی ندارد.
- loopback در برابر کاربران یا processهای دیگر همان سرور احراز هویت محسوب
  نمی‌شود؛ از میزبان تک‌کاربرهٔ قابل‌اعتماد یا ایزوله‌سازی سیستم‌عامل/شبکه
  استفاده کنید.
- هرگز پورت HTTP را (که پیش‌فرض آن `4173` است) مستقیماً روی اینترنت باز
  نکنید و listener را به `0.0.0.0` تغییر ندهید.
- برای اتصال از راه دور از SSH tunnel دارای احراز هویت استفاده کنید.
- روی سرور بهتر است برنامه با کاربر کم‌اختیار، container یا VM جدا اجرا شود.
- گزینهٔ `--yolo` فقط sandbox و درخواست‌های تأیید Codex را غیرفعال می‌کند و
  تنظیمات Claude را تغییر نمی‌دهد.
- حالت غیرتعاملی `--print` در Claude دیالوگ workspace trust را رد می‌کند؛
  گفتگوی Claude را فقط داخل پوشهٔ کاری مورداعتماد شروع کنید.
- Codex Web برای گفتگوی تازهٔ Claude در ابتدا حالت `acceptEdits` را انتخاب
  می‌کند؛ این حالت اجازهٔ ویرایش فایل‌های پوشهٔ کاری را بدون سؤال می‌دهد.
  `bypassPermissions` دسترسی بسیار گسترده‌تری ایجاد می‌کند. پیش از شروع گفتگو
  این انتخاب را بررسی کنید.

پیش از اجرای برنامه روی سرور، [SECURITY.md](SECURITY.md) را بخوانید.

## پیش‌نیازها

- Linux، macOS یا Windows از طریق WSL؛ نسخهٔ فعلی روی Linux تست شده و
  Windows بومی هنوز تأیید نشده است.
- Node.js نسخهٔ ۲۲ یا جدیدتر؛ از یک نسخهٔ LTS تحت پشتیبانی استفاده کنید.
- نسخه‌ای جدید از Codex CLI دارای فرمان آزمایشی `app-server`، اگر از provider
  کدکس استفاده می‌کنید
- نسخه‌ای جدید از Claude Code CLI، اگر از provider کلود استفاده می‌کنید
- login، provider profile یا credential محیطی تنظیم‌شده برای هر providerی که
  قصد استفاده از آن را دارید

نسخهٔ فعلی با Codex CLI `0.145.0` تست شده است. نسخه‌های جدید دیگر نیز ممکن
است کار کنند، اما protocol آزمایشی app-server می‌تواند تغییر کند. فرمان‌های
احراز هویت و flagهای Claude که اینجا مستند شده‌اند با Claude Code `2.1.220`
بررسی شده‌اند. اتصال Claude به فرمت streaming غیرتعاملی و ساختار sessionهای
محلی Claude Code نیز وابسته است؛ هنگام استفاده از این provider، Claude Code
را به‌روز نگه دارید. فایل `.nvmrc` موجود در پروژه برای کاربران `nvm`،
Node.js 24 را انتخاب می‌کند.

providerهای موردنیاز را نصب و احراز هویت کنید:

```bash
# Codex
npm install --global @openai/codex
codex login

# Claude Code — ابتدا راهنمای رسمی نصب را دنبال کنید
claude --version
claude auth login
```

روش‌های فعلی نصب در
[راهنمای راه‌اندازی Claude Code](https://code.claude.com/docs/en/setup)
توضیح داده شده‌اند.

روی سرور بدون رابط گرافیکی می‌توانید از device authentication استفاده کنید:

```bash
codex login --device-auth
```

providerهای سفارشی و credentialهای محیطی درست مانند CLI کار می‌کنند. اگر
تنظیمات provider شما به OpenAI login وابسته نیست، انجام `codex login` نیز
ضروری نیست.

## نصب

```bash
git clone https://github.com/msadegh/codex-web.git
cd codex-web
npm install
npm install --global .
```

فرمان آخر launcher سراسری `codex-web` را نصب می‌کند. برای checkout توسعه‌ای
می‌توانید به‌جای آن از `npm link` استفاده کنید.

بدون نصب launcher سراسری نیز می‌توانید از داخل checkout کدکس وب اجرا کنید؛
پروژهٔ هدف را صریحاً مشخص کنید:

```bash
CODEX_WEB_CWD=/absolute/path/to/project npm start -- --search
```

## استفادهٔ لوکال

ابتدا وارد پروژه‌ای شوید که می‌خواهید Codex روی آن کار کند و سپس Codex Web
را اجرا کنید:

```bash
cd /path/to/your/project
codex-web
```

مرورگر روی <http://127.0.0.1:4173> باز می‌شود. برای توقف برنامه `Ctrl+C`
بزنید.

چند نمونه:

```bash
# مجوزهای تعاملی پیشنهادی
codex-web --sandbox workspace-write --ask-for-approval on-request --search

# استفاده از یک profile کدکس
export YOUR_PROVIDER_API_KEY=...
codex-web -p work --search

# مشابه اجرای کاملاً خودکار CLI — خطرناک
codex-web -p work --yolo --search

# اجرا بدون بازکردن خودکار مرورگر
codex-web --no-open
```

فرایند فرزند `codex app-server` تمام متغیرهای محیطی `codex-web` را به ارث
می‌برد. بنابراین کلید provider باید در محیط shell یا سرویس بماند و هرگز
داخل repository قرار نگیرد.

Claude Code با گزینه‌های `--print --output-format stream-json` اجرا می‌شود؛
در این حالت دیالوگ workspace trust رد می‌شود و Codex Web نمی‌تواند prompt
تعاملی مجوزهای Claude را نمایش دهد؛ بنابراین فقط از پوشهٔ کاری مورداعتماد
استفاده کنید. `acceptEdits` ویرایش و عملیات معمول فایل را در همان پوشه خودکار
مجاز می‌کند و ابزارهای تأییدنشدهٔ دیگر ممکن است turn را با خطا متوقف کنند.
`dontAsk` ابزارهای ازپیش‌تأییدنشده را خودکار رد می‌کند، `plan` فقط خواندنی است
و `bypassPermissions` بیشتر بررسی‌های مجوز را نادیده می‌گیرد و خطرناک است.
ruleهای موجود `permissions.allow` و `permissions.deny` در Claude همچنان اعمال
می‌شوند. احراز هویت و تنظیمات محیطی معمول Claude استفاده می‌شوند و کلید API
هرگز به مرورگر ارسال یا در تنظیمات مرورگر ذخیره نمی‌شود. معنی دقیق modeها و
ruleها در
[راهنمای مجوزهای Claude Code](https://code.claude.com/docs/en/permissions)
قرار دارد.

### گزینه‌های پشتیبانی‌شدهٔ Codex CLI

Codex Web این گزینه‌ها را برای provider کدکس تبدیل می‌کند:

| گزینه | رفتار |
| --- | --- |
| `-p` و `--profile` | اعمال scalarهای top-level از فایل `$CODEX_HOME/<name>.config.toml` |
| `-s` و `--sandbox` | sandbox پیش‌فرض گفتگوهای جدید و ازسرگرفته‌شدهٔ Codex |
| `-a` و `--ask-for-approval` | approval policy پیش‌فرض گفتگوهای جدید و ازسرگرفته‌شدهٔ Codex |
| `--yolo` و `--dangerously-bypass-approvals-and-sandbox` | انتخاب `danger-full-access` و policy برابر `never` |
| `--search` | فعال‌سازی جستجوی زندهٔ وب |
| `-c`، `--enable`، `--disable` و `--strict-config` | گزینه‌های سراسری سازگار Codex که پیش از `app-server` ارسال می‌شوند |
| `--no-open` | جلوگیری از بازشدن خودکار مرورگر |

در حال حاضر Codex app-server گزینهٔ profile ندارد؛ به همین دلیل Codex Web
مقادیر scalar سطح اول profile را به overrideهای `-c` تبدیل می‌کند. جدول‌های
TOML داخل profile فعلاً نادیده گرفته می‌شوند. secretها را به‌جای profile در
متغیرهای محیطی قرار دهید، زیرا overrideهای خط فرمان ممکن است در فهرست
processهای سرور دیده شوند. این گزینه‌های Codex، permission mode کلود را تغییر
نمی‌دهند؛ آن را جداگانه در تنظیمات مرورگر انتخاب کنید.

برای دیدن راهنمای محلی اجرا کنید:

```bash
codex-web --help
```

### متغیرهای محیطی

| متغیر | مقدار پیش‌فرض | کاربرد |
| --- | --- | --- |
| `CODEX_WEB_PORT` | `4173` | پورت HTTP لوکال |
| `CODEX_WEB_CWD` | پوشهٔ اجرای فرمان | پوشهٔ کاری پیش‌فرض |
| `CODEX_WEB_NO_OPEN` | تنظیم‌نشده | مقدار `1` مانع بازشدن مرورگر می‌شود |
| `CODEX_WEB_UPLOAD_DIR` | پوشهٔ cache کدکس وب | محل ذخیرهٔ تصاویر آپلودشده |
| `XDG_CACHE_HOME` | در Linux برابر `~/.cache` | پوشهٔ پایهٔ cache |
| `CODEX_BIN` | `codex` | مسیر فایل اجرایی Codex |
| `CLAUDE_BIN` | `claude` | مسیر فایل اجرایی Claude Code |
| `CLAUDE_CONFIG_DIR` | `~/.claude` | تنظیمات، credentialها، pluginها و sessionهای native کلود |
| `CLAUDE_WEB_DATA_DIR` | `~/.cache/codex-web/claude` | metadata و تاریخچهٔ گفتگوهای Claude |

برای سازگاری با buildهای اولیهٔ توسعه، اگر `CLAUDE_CONFIG_DIR` تنظیم نشده
باشد Codex Web مقدار `CLAUDE_HOME` را به‌عنوان fallback می‌پذیرد. در تنظیمات
جدید از متغیر رسمی Claude Code یعنی `CLAUDE_CONFIG_DIR` استفاده کنید.

### تنظیمات مختص هر provider در مرورگر

| تنظیم | Codex | Claude |
| --- | --- | --- |
| پوشهٔ کاری و مدل | برای گفتگوهای تازه اعمال می‌شود | برای گفتگوهای تازه اعمال می‌شود |
| Reasoning effort | مقادیر دردسترس به مدل Codex بستگی دارند | `low`، `medium`، `high`، `xhigh` یا `max`؛ مقدار `ultra` ارسال نمی‌شود |
| Sandbox، approval policy و personality | اعمال می‌شود | مخفی است و برای Claude ارسال نمی‌شود |
| Permission mode کلود | استفاده نمی‌شود | برای گفتگوهای تازهٔ ساخته‌شده در وب اعمال می‌شود |

گفتگوهای ساخته‌شده در وب provider و تنظیمات ذخیره‌شدهٔ session خود را حفظ
می‌کنند. sessionهای native کلود که override صریحی در Codex Web ندارند، هنگام
ادامه از permission پیش‌فرض خود Claude Code استفاده می‌کنند.

گفتگوهای Claude که از Codex Web ساخته می‌شوند در `CLAUDE_WEB_DATA_DIR` ذخیره
می‌شوند. sessionهای قبلی Claude Code از `CLAUDE_CONFIG_DIR/projects` پیدا شده
و با session ID اصلی خودشان ادامه داده می‌شوند. فرایند پیدا‌کردن transcriptها
را تغییر نمی‌دهد، اما ادامه‌دادن گفتگو باعث می‌شود خود Claude Code تاریخچهٔ
native آن را به‌روز کند. از هر دو پوشه محافظت کنید، چون ممکن است شامل source
code، ورودی و خروجی ابزارها یا اطلاعات حساس باشند.

## فرمان‌های اسلش

با تایپ `/` در کادر پیام، منوی فرمان‌ها باز می‌شود. سپس می‌توانید با ادامهٔ
تایپ، فهرست را فیلتر کنید یا فرمان را با کیبورد، ماوس یا لمس انتخاب کنید.

| فرمان | عملکرد |
| --- | --- |
| `/goal` | ساخت یا ویرایش Goal ماندگار برای گفتگوی فعلی Codex |
| `/plan` | روشن یا خاموش‌کردن Plan mode بومی برای turnهای بعدی Codex؛ `Shift+Tab` داخل composer نیز همین کار را می‌کند |
| `/compact` | فشرده‌سازی بومی context در Codex؛ فقط برای یک گفتگوی موجود و بیکار در دسترس است |
| `/new` | شروع یک گفتگوی جدید |
| `/clear` | پاک‌کردن نمای فعلی و شروع یک گفتگوی تازه |
| `/resume` | بازکردن فهرست گفتگوهای ذخیره‌شده |
| `/status` | نمایش وضعیت گفتگوی فعلی |
| `/model` | بازکردن تنظیمات مدل |
| `/permissions` | بازکردن تنظیمات مجوز provider انتخاب‌شده |
| `/settings` | بازکردن همهٔ تنظیمات گفتگو |
| `/help` | نمایش فهرست فرمان‌های پشتیبانی‌شده |

فرمان اسلش ناشناخته برای مدل ارسال نمی‌شود. در حال حاضر Codex Web فقط
فرمان‌های فهرست‌شده در بالا را پشتیبانی می‌کند و همهٔ فرمان‌های اسلش رابط
ترمینالی Codex یا Claude در دسترس نیستند. این فرمان‌ها را خود Codex Web اجرا
می‌کند و مستقیماً به provider انتخاب‌شده نمی‌فرستد.

## گفتگوهای هم‌زمان

یک فرایند Codex Web می‌تواند چند گفتگوی Codex و Claude را به‌صورت هم‌زمان اجرا
کند. یک تسک را شروع کنید، **گفتگوی تازه** را بزنید و تسک دیگری آغاز کنید.
وضعیت گفتگو، پیام‌ها و eventهای استریم‌شده براساس provider و thread ID
مسیریابی می‌شوند و با هم قاطی نمی‌شوند. سؤال‌های تعاملی مجوز و ورودی مربوط به
گفتگوهای Codex هستند؛ رفتار غیرتعاملی مجوزهای Claude بالاتر توضیح داده شد.

Codex Web یک فرایند app-server کدکس را نگه می‌دارد و threadهای آن را مسیریابی
می‌کند. هر turn فعال Claude در یک فرایند فرزند غیرتعاملی و جداگانهٔ Claude CLI
اجرا می‌شود و تب ترمینال قابل‌مشاهده‌ای باز نمی‌کند. بنابراین کار گفتگوهای جدا
می‌تواند به‌صورت موازی پیش برود.

همهٔ گفتگوها همچنان کاربر سیستم‌عامل، environment، CPU، RAM و احتمالاً
working tree یکسان دارند. بنابراین دو agent ممکن است هنگام ویرایش هم‌زمان
یک فایل با هم تداخل داشته باشند، هرچند وضعیت گفتگوهایشان ایزوله است.

چند تب مرورگر می‌توانند به یک سرور وصل شوند. صدای پایان کار بین تب‌ها تکراری
پخش نمی‌شود.

## تصاویر، Dictation، ناوبری و اعلان پایان کار

با دکمهٔ تصویر می‌توانید حداکثر ۲۰ تصویر انتخاب کنید یا اسکرین‌شات را مستقیماً
داخل composer پیست کنید. فرمت‌های PNG، JPEG، WebP، GIF، AVIF و BMP تا سقف
۲۵ مگابایت برای هر تصویر پشتیبانی می‌شوند.

مرورگر مسیر absolute فایل انتخاب‌شده را نشان نمی‌دهد. در نتیجه Codex Web هر
تصویر را روی ماشینی که سرور روی آن اجرا شده—معمولاً در
`~/.cache/codex-web/uploads`—کپی کرده و مسیر absolute سمت سرور را داخل prompt
می‌گذارد. هنگام اتصال راه دور، تصویر لپ‌تاپ یا گوشی از طریق SSH tunnel روی
سرور آپلود می‌شود.

فایل‌های آپلودشده در cache باقی می‌مانند تا مسیر گفتگوهای قدیمی همچنان معتبر
باشد. تصاویر حساس بلااستفاده را بعد از بررسی، دستی پاک کنید.
پاک‌سازی خودکار یا سقف کلی برای cache وجود ندارد؛ در اجرای طولانی‌مدت فضای
دیسک را پایش کنید.

دکمهٔ میکروفون از Speech Recognition مرورگر استفاده می‌کند و متن Dictation را
پیش از ارسال داخل composer می‌گذارد تا قابل ویرایش باشد. در دسترس‌بودن این
قابلیت و محلی یا سرویس‌محور بودن پردازش گفتار به مرورگر بستگی دارد و به مجوز
میکروفون نیاز دارد. هنگام اتصال راه دور از اندروید، اگر Chrome دکمهٔ داخل صفحه
را مسدود کرد، composer را انتخاب و از میکروفون Gboard استفاده کنید؛ نتیجه همان
متن قابل‌ویرایش و قابل‌صف‌شدن است.

دکمه‌های بالا و پایین هدر گفتگو میان پیام‌های خودتان جابه‌جا می‌شوند. مرورگر
برای اجازهٔ پخش صدای پایان کار نیاز دارد ابتدا یک بار روی صفحه کلیک کنید یا
کلیدی بزنید.

با بازکردن هر گفتگو، شناسهٔ آن داخل پارامتر کاربرپسند `?session=` در URL
لوکال قرار می‌گیرد. refresh صفحه و دکمه‌های Back و Forward مرورگر همان انتخاب
را بازیابی می‌کنند. لینک‌های قدیمی `?thread=` نیز همچنان کار می‌کنند و خودکار
به پارامتر جدید تبدیل می‌شوند. مقدار این پارامتر به گفتگوی provider اشاره
می‌کند که در Codex app-server داخل کد «thread» نام دارد؛ این شناسه ابزار احراز
هویت نیست و سرور localhost-only را از راه دور دردسترس قرار نمی‌دهد.

## اجرا روی سرور

Codex یا Claude و تمام فرمان‌ها روی سرور اجرا می‌شوند و مرورگر فقط رابط کاربری
است.

### ۱. اجرای Codex Web روی سرور

Codex Web و CLI هر providerی را که قصد استفاده از آن دارید روی سرور نصب و همان
providerها را احراز هویت کنید. برای نمونه، اجرای زیر Codex را با پیش‌فرض‌های
محافظه‌کارانه راه می‌اندازد:

```bash
cd /path/to/server/project
codex-web --no-open --sandbox workspace-write --ask-for-approval on-request --search
```

این گزینه‌های sandbox و approval خط فرمان فقط Codex را تنظیم می‌کنند. پیش از
شروع یک گفتگوی Claude، permission mode آن را جداگانه در مرورگر انتخاب کنید.

اگر برنامه باید بعد از قطع SSH روشن بماند، از `tmux`، `screen` یا یک سرویس
user-level با تنظیمات دقیق استفاده کنید. credentialها را بیرون repository
نگه دارید.

اگر قبلاً یک profile برای provider سفارشی ساخته‌اید، می‌توانید از این حالت
اختیاری استفاده کنید:

```bash
export YOUR_PROVIDER_API_KEY=...
codex-web --no-open -p work --sandbox workspace-write --ask-for-approval on-request --search
```

### ۲. ساخت tunnel از لپ‌تاپ

```bash
ssh -o ExitOnForwardFailure=yes -N \
  -L 127.0.0.1:4173:127.0.0.1:4173 USER@SERVER_IP
```

این ترمینال را باز نگه دارید و <http://127.0.0.1:4173> را باز کنید.

اگر پورت `4173` لپ‌تاپ اشغال است:

```bash
ssh -o ExitOnForwardFailure=yes -N \
  -L 127.0.0.1:44173:127.0.0.1:4173 USER@SERVER_IP
```

سپس <http://127.0.0.1:44173> را باز کنید.

### اتصال از گوشی

از یک برنامهٔ SSH با پشتیبانی از local port forwarding مثل Termius، Blink یا
Termux استفاده کنید و این نگاشت را بسازید:

```text
local 127.0.0.1:4173 → server 127.0.0.1:4173
```

SSH tunnel را فعال نگه دارید و `http://127.0.0.1:4173` را در مرورگر گوشی باز
کنید. ممکن است سیستم‌عامل گوشی برنامهٔ SSH را در پس‌زمینه متوقف کند؛ در صورت
نیاز اجازه دهید فعال بماند.

Tailscale می‌تواند خود اتصال SSH را امن کند، اما دسترسی به Codex Web همچنان
باید از طریق loopback forwarding انجام شود. در این نسخه اتصال مستقیم و
استقرار پشت reverse proxy عمومی—حتی با احراز هویت proxy—پشتیبانی نمی‌شود؛
روش مستند اتصال راه دور همان SSH loopback forwarding است.

## به‌روزرسانی

ابتدا Codex Web را متوقف و سپس checkout را به‌روزرسانی کنید:

```bash
cd /path/to/codex-web
git pull --ff-only
npm install
npm install --global .
```

اگر تغییر protocol یا فرمت خروجی provider باعث ناسازگاری شد، Codex CLI یا
Claude Code CLI مربوط را نیز به‌روزرسانی کنید.

## حذف برنامه و داده‌های محلی

```bash
npm uninstall --global codex-web
```

بعد می‌توانید repository کلون‌شده را حذف کنید. این کار موارد زیر را پاک
نمی‌کند:

- login، تنظیمات یا sessionهای Codex CLI
- تنظیمات، credentialها، pluginها یا sessionهای native کلود در
  `CLAUDE_CONFIG_DIR` که معمولاً `~/.claude` است
- تاریخچهٔ نرمال‌شدهٔ Claude در `CLAUDE_WEB_DATA_DIR` که معمولاً
  `~/.cache/codex-web/claude` است
- تصاویر آپلودشده در cache کدکس وب که معمولاً
  `~/.cache/codex-web/uploads` است

فقط زمانی که دیگر به این داده‌ها نیاز ندارید مسیرهای مربوط را بررسی و دستی
پاک کنید. حذف `CLAUDE_CONFIG_DIR` روی خود Claude Code نیز اثر می‌گذارد و فقط
داده‌های Codex Web را حذف نمی‌کند.

## رفع اشکال

- **فرمان `codex` پیدا نمی‌شود:** `codex --version` را اجرا یا `CODEX_BIN` را
  روی مسیر کامل فایل اجرایی تنظیم کنید.
- **فرمان `claude` پیدا نمی‌شود:** `claude --version` را اجرا یا `CLAUDE_BIN`
  را روی مسیر کامل فایل اجرایی تنظیم کنید.
- **خطای احراز هویت:** با `codex login status` بررسی کنید. کاربران OpenAI
  login می‌توانند `codex logout` و سپس `codex login` اجرا کنند؛ کاربران
  provider سفارشی باید profile و environment را بررسی کنند.
- **خطای احراز هویت Claude:** ابتدا `claude auth status` و در صورت نیاز
  `claude auth login` را اجرا کنید.
- **sessionهای Claude دیده نمی‌شوند:** مطمئن شوید `CLAUDE_CONFIG_DIR` به همان
  پوشهٔ تنظیماتی اشاره می‌کند که فرایند Claude CLI استفاده می‌کند.
- **ابزار Claude رد شد:** Claude غیرتعاملی اجرا می‌شود. permission mode یا
  ruleهای Claude را طوری تنظیم کنید که فقط ابزارهای لازم از قبل مجاز باشند؛
  صرفاً برای پنهان‌کردن خطای تنظیمات سراغ `bypassPermissions` نروید.
- **پورت اشغال است:** با `CODEX_WEB_PORT=4180 codex-web` اجرا کنید و URL یا
  SSH mapping را مطابق همان پورت تغییر دهید.
- **پوشهٔ کاری اشتباه است:** برنامه را داخل پروژهٔ هدف اجرا کنید،
  `CODEX_WEB_CWD` را تنظیم کنید یا پیش از شروع گفتگو آن را در تنظیمات تغییر
  دهید.
- **SSH tunnel قطع شده است:** دوباره tunnel را برقرار کنید؛ ممکن است فرایند
  روی سرور همچنان روشن باشد.
- **صدای پایان کار پخش نمی‌شود:** یک بار با صفحه تعامل کنید و مجوز صدای
  مرورگر را بررسی کنید.
- **تصویر رد می‌شود:** فرمت، سقف ۲۵ مگابایت و permission پوشهٔ cache را
  بررسی کنید.
- **خطای protocol provider:** Codex CLI یا Claude Code CLI و Codex Web را
  به‌روزرسانی و restart کنید. protocol مربوط به Codex app-server و فرمت stream
  کلود می‌توانند تغییر کنند.
